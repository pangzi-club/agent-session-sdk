Project map / Go SDK

从本地会话文件，到统一的数据接口。

这个仓库把多个 Coding Agent 各自的存储格式收敛为一组 Go API：扫描会话、读取 Transcript、提取 Token 用量、估算费用，并可通过 SQLite 为会话列表提供增量索引。

整体数据流

文件系统和 Agent 自有数据库是事实来源；SDK 做读取、归一化和派生，不负责修改或删除源会话。

本地 Agent StoreJSONL、JSON、目录树或 SQLite；缺失的 Agent Store 视作空数据。
扫描与提取按 Agent 结构发现会话元数据；用量解析器单独提取事件与 Token 记录。
统一模型SessionInfo、Entry、UsageRecord 及详细失败报告。
消费端Go API、JSON CLI、可选会话索引、模型价格估算。

普通扫描

ScanSessionsDetailed 并行扫描已注册 Agent，保留成功结果并返回逐 Agent 错误。

索引扫描

SessionIndex.Refresh 比较 Store 签名，仅重扫发生变化的 Agent；索引是可重建缓存。

功能边界

会话扫描

ScanSessions 是兼容旧行为的简便接口；ScanSessionsDetailed 返回部分成功结果和逐 Agent 失败。未安装的 Agent 不算失败。

Transcript

LoadTranscript 将不同格式归一化成 []Entry；Cache 提供有界 LRU，并按文件大小和修改时间失效。

用量与估价

ScanAllUsageDetailed 隔离 Agent 失败；Summarize 聚合 Token 与活跃时长。未知模型不会猜价格，而是计入未定价 Token。

SQLite 索引

默认保存于 <home>/.agent-session-sdk/home.sqlite。只存会话元数据和 Token 汇总，不存 Transcript 或原始用量事件。

CLI 命令

命令作用备注
sessions列出 Agent 会话可用 --index 走 SQLite
usage输出用量记录和关联会话--cost 附加费用估算
summary输出逐 Agent 用量汇总不支持本地用量数据的 Agent 不出现
transcript输出指定会话 Transcript需要 --agent 和 --session
search搜索索引中的会话标题、工作区和 ID支持子串搜索及分页参数
错误语义：CLI 成功 Agent 的 JSON 仍输出到 stdout，扫描失败写到 stderr 并返回退出码 1；参数错误返回 2。这个约定能让自动化调用区分“没有数据”和“数据未能读取”。

输出契约

这个 SDK 的核心价值不只是解析文件，也包括稳定地复现消费者已经使用的数据形状。

Go 类型用途契约注意点
SessionInfo单个会话元数据字段次序、JSON key、空值与省略规则和 TS 契约对齐
SessionScanResult按 Agent 分组的会话列表包含 canDeleteSessions 能力声明，不执行删除
Entry / ToolCall统一 Transcript 内容将工具调用和结果压成消费者可展示的条目
UsageRecord / UsageScanToken、事件计数与关联会话用量字段包含输入、输出、缓存、活跃时长及可选 credits
AgentUsageSummary按 Agent 汇总用量会话数和请求数用 int，Token 数和活跃时长用 float64
兼容性重点：contract.go 的字段顺序、omitempty 和显式 null 有意保持与 TypeScript 消费端相同。改动结构体标签前，应该同时检查消费端 IPC 类型和定价版本测试。

会话列表与搜索 · []SessionScanResult

每组包含一个 Agent 的会话元数据。Title == nil 输出 "title": null，Blank == nil 时省略 blank，指向 false 时则输出 "blank": false。下面展示 源码中的公开字段。

type SessionInfo struct {
    ID         string      `json:"id"`
    Workspace  string      `json:"workspace"`
    Title      *string     `json:"title"`
    Blank      *bool       `json:"blank,omitempty"`
    CreatedAt  float64     `json:"createdAt"`
    UpdatedAt  float64     `json:"updatedAt"`
    SizeBytes  float64     `json:"sizeBytes"`
    FilePath   *string     `json:"filePath,omitempty"`
    TokenUsage *[5]float64 `json:"tokenUsage,omitempty"`
}

type SessionScanResult struct {
    AgentID           string        `json:"agentId"`
    AgentName         string        `json:"agentName"`
    Sessions          []SessionInfo `json:"sessions"`
    CanDeleteSessions *bool         `json:"canDeleteSessions,omitempty"`
}

会话内容 · []Entry

每条内容承载文本、思考或工具调用。Timestamp 是 Unix 毫秒时间戳，DurationMs 是以毫秒计的耗时。

type Role string

const (
    RoleUser      Role = "user"
    RoleAssistant Role = "assistant"
    RoleSystem    Role = "system"
)

type ToolKind string

const (
    ToolFile    ToolKind = "file"
    ToolCommand ToolKind = "command"
    ToolSearch  ToolKind = "search"
    ToolOther   ToolKind = "other"
)

type ToolCall struct {
    Name   string   `json:"name"`
    Title  string   `json:"title"`
    Meta   string   `json:"meta"`
    Kind   ToolKind `json:"kind"`
    ID     string   `json:"id,omitempty"`
    Input  string   `json:"input,omitempty"`
    Output string   `json:"output,omitempty"`
    Failed bool     `json:"failed,omitempty"`
}

type Entry struct {
    Role       Role       `json:"role"`
    Text       string     `json:"text"`
    Thinking   string     `json:"thinking,omitempty"`
    Tools      []ToolCall `json:"tools,omitempty"`
    Timestamp  float64    `json:"timestamp"`
    DurationMs float64    `json:"durationMs,omitempty"`
}

Records 保存用量记录，Sessions 保存关联会话元数据。Model、工具名或技能名计数为 nil 时输出 null，Credits 为 nil 时省略。

    SkillCallsByName *map[string]float64 `json:"skillCallsByName"`

type UsageSession struct {
    ID         string      `json:"id"`
    AgentID    string      `json:"agentId"`

type UsageScan struct {

架构评估与改进建议

整体结构适合当前单一 Go 包和多格式读取器的规模；不建议仅为“分层”而拆包。前两项已落地，后续建议保留为独立工作。

已落地把 Transcript Loader 能力并入 Agent 定义

每个 agentDef 现在关联自身 Transcript loader，LoadTranscript 从注册表分派；Cindy 仍按会话的 transcriptFormat 选择具体解析器，未知 Agent 保留通用解析回退。

回归覆盖了通用格式、Cindy 各类 Transcript 以及 Cindy 会话从 SQLite 索引读回后的解析。

已落地用共享注册数据维护用量能力和顺序

用量解析器和明确的 usageOrder 都在 agentDef；usage.go 按该顺序生成扫描列表，不再维护第二份 Agent ID 清单。

测试锁定扫描 Agent 顺序、用量 Agent 顺序，并检查 loader 与用量配置的一致性。

后续为索引刷新成本建立可观测性，再优化签名扫描

增量索引避免重复解析，但每次 refresh 仍要遍历 Store 并对相对路径、大小、mtime 做哈希；大型 Store 的未变化刷新仍可能受文件遍历主导。Cindy 已有针对性签名过滤，说明不同 Store 的有效文件范围并不完全相同。

已添加 100 / 1000 会话的未变化刷新基准；合成 Claude Store 的本机参考值约为 0.57 / 4.30 ms（Apple M4，非稳定性能承诺）。优化前还应采集代表性真实 Store 的逐 Agent 签名耗时。

后续继续扩展跨语言契约覆盖

现有 JSON golden 测试覆盖 session、transcript、usage 的字段顺序、空值和省略行为；定价版本也已有跨语言测试。剩余风险是这些样例还未与消费端的 TypeScript fixture 自动比对。

建议：下一步接入消费端现有 IPC fixture 做双向比对；只有当两侧维护流程允许时再考虑由单一 schema 生成类型。

保持现状根目录单包暂时不是需要解决的问题

扫描器、共享解析辅助函数与统一输出类型高度互相依赖；拆包会增加导出 API 和依赖方向成本。按职责命名的 Go 文件已经提供了轻量边界，根包也让 SDK 使用方只需一个导入路径。

建议：继续按 Agent 和能力拆文件；当出现可独立演进、依赖边界清晰的子系统时，再考虑 internal/ 或子包。公共契约类型继续留在根包以降低迁移成本。
